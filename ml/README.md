# WhistleDrop — offline triage pipeline

The training half of the AI-assisted triage extension. Everything here runs
**offline and independently of the API**: no FastAPI, no database, no
application settings. Training needs a checkout and a CSV.

> **The model in this directory is trained on synthetic data and is not fit for
> production use.** No labelled corpus of real reports exists in this project.
> See [`reports/model-card.md`](reports/model-card.md).

## Layout

```
ml/
├── data/                        datasets (synthetic; real exports go in data/private/, gitignored)
│   └── synthetic_reports.csv
├── artifacts/                   trained models — gitignored, rebuilt by training
│   └── whistledrop-category-v1/
│       ├── category/model.joblib
│       └── metadata/model-metadata.json
├── reports/
│   ├── model-evaluation.md      regenerated by every training run
│   └── model-card.md            maintained by hand
└── src/
    ├── config.py                paths, seed, version, label sets
    ├── generate_synthetic.py    the synthetic dataset generator
    ├── data.py                  loading, validation, leakage checks, splitting
    ├── features.py              TF-IDF configuration
    ├── keywords.py              model-associated keyword extraction
    ├── priority.py              the deterministic priority heuristic
    ├── evaluate.py              metrics, baseline, confusion matrix
    └── train_category.py        the entrypoint
```

## Running it

```bash
# 1. Generate the synthetic development dataset (already committed; this
#    regenerates it byte-identically from the seed).
python -m ml.src.generate_synthetic

# 2. Validate, split, train, evaluate, and write artifacts + report.
python -m ml.src.train_category
```

The second command does everything in one pass and prints what it found. It
exits non-zero if the dataset is missing (2), is not trainable (3), or if text
leaked between splits (4).

## Design notes

**Why TF-IDF and logistic regression.** It is fast, it trains in under a
second, and — most importantly here — it is *auditable*. Every prediction
decomposes into term contributions that can be shown to a moderator. In a
system where a suggestion sits beside a confidential report, being able to say
exactly which words moved a decision is worth more than a few points of
accuracy from something opaque. No deep learning, no embeddings, no LLM:
nothing on the roadmap needs them, and each would cost explainability and
introduce a dependency that wants report text sent somewhere.

**Why the split is grouped by text.** The dataset contains duplicate
descriptions, as a real one would. A plain stratified split would put two
copies of one report on opposite sides of the boundary, and the model would
then be scored on text it had memorised. Splitting on distinct normalised text
makes that impossible; the training run asserts zero overlap and refuses to
train otherwise.

**Why three splits.** The only model choice made anywhere — balanced class
weights or not — is decided on *validation*. The test set is read once, at the
end. Choosing on test and then reporting test numbers is how a pipeline
produces a score it cannot reproduce on anything else.

**Why priority is a heuristic.** There are no priority labels. Inventing some
would mean the model learned whatever rule invented them, and using
time-to-resolution as a proxy would encode past staffing rather than severity.
A written-down rule is the honest option and is fully explainable. It becomes
the baseline to beat when real severity labels exist.

## Privacy rules for this directory

- **Never commit real report text.** `ml/data/private/` is gitignored and is
  where any real export belongs.
- Training is local and offline. No report text is sent to any external
  service, API or model provider.
- Artifacts contain the fitted vectoriser and classifier, never training
  documents.
- Metadata records the dataset's name and SHA-256, never its contents.
- No secrets go into artifacts. A test asserts it.

## Relationship to `app/`

One-way and minimal: `ml/` imports nothing from `app/`, and `app/` currently
imports nothing from `ml/`. The category and priority label sets are
deliberately restated in `ml/src/config.py` rather than imported from
`app.models.enums`, so that training runs without the application's
dependencies — and a test asserts the two definitions stay identical, so the
duplication cannot drift.

Phase 7 is what loads these artifacts inside the API. Nothing here does.
