# Model card — WhistleDrop category suggester

| | |
|---|---|
| **Name** | WhistleDrop advisory category suggester |
| **Version** | `whistledrop-category-v1` |
| **Type** | TF-IDF (word 1–2-grams) → multinomial logistic regression |
| **Task** | Suggest one of five categories for a report, with a probability |
| **Status** | **Not fit for production use.** Trained on synthetic data — see below |
| **Owner** | WhistleDrop project |
| **Artifact** | `ml/artifacts/whistledrop-category-v1/` |

---

## The one thing to read first

This model was trained on **synthetic data**. No labelled corpus of real
whistleblowing reports exists in this project, so the training set was
generated from templates in order to build and test the pipeline.

The evaluation numbers in `model-evaluation.md` are high. They measure how well
a linear model recovers the rules of a template generator, which is an easy
problem. **They say nothing about how this model would classify a real report**,
and they must not be quoted as though they did.

What has been demonstrated is that the pipeline works: data validation, leakage
detection, a grouped stratified split, feature extraction, training, honest
evaluation against a baseline, and reproducible artifacts. What has not been
demonstrated is that the model is useful.

## Intended use

- **Suggesting** a category to a human moderator reviewing a report, alongside
  a model probability, so that an obvious `SECURITY` report is easier to spot
  in a long queue.
- **Ordering** work, in combination with the separate priority heuristic.
- As a **baseline** to beat once real labelled data exists.

The suggestion is advisory. A moderator sets the official category; this model
never does.

## Uses this model is not fit for

- **Deciding a report's category or status.** The system is built so that it
  structurally cannot: suggestions live in `report_triage`, a separate table
  from `reports`, and nothing in the moderation workflow reads them.
- **Filtering or de-prioritising reports without human review.** A report the
  model is confident about is still a report a person must read.
- **Closing, dismissing or routing a report automatically.**
- **Any judgement about the reporter.** The model sees text and nothing else —
  there is no reporter identity in the system to judge.
- **Anything outside English-language workplace reports.**
- **Legal, disciplinary or safety decisions.**

## Input

A single field: the report's `description`, as written.

Nothing else. Not the category (that is the target), not the status (a
moderator sets it after reading), not the id, the timestamps, the case code or
its hash, and not the evidence URL. `ml/src/data.py` names these in
`FORBIDDEN_FEATURE_COLUMNS` and drops them from any dataset file that carries
them, because each would leak the answer or identify the record.

## Output

| Field | Meaning |
|---|---|
| `suggested_category` | One of `SECURITY`, `HARASSMENT`, `CORRUPTION`, `TECHNICAL`, `OTHER` |
| `category_confidence` | The model's probability for that category, 0.0–1.0 |
| `keywords` | Terms in the report that most pushed the model towards it |

**On the word "confidence."** This is a model probability, not a certainty and
not a correctness estimate. The model has not been calibration-tested, so a
value of 0.9 does not mean "right nine times out of ten". It means the softmax
put 0.9 there. The API and the moderator interface use the wording "AI
confidence" or "model probability" and never "certainty".

**On the keywords.** For a linear model these are exact contributions —
`tf-idf value × coefficient` for terms present in the document — so they
faithfully describe *what moved this model's decision*. They are **not** causal
explanations and not reasons the report belongs to that category. A term can
rank highly because it carries real signal or because it happened to correlate
with the class in training; the arithmetic cannot distinguish the two.

## Training data

- **Source**: generated by `ml/src/generate_synthetic.py`, committed as
  `ml/data/synthetic_reports.csv`
- **Nature**: synthetic. Templated subjects, predicates and contexts, with
  deliberate class imbalance, planted duplicates, planted conflicting labels,
  and a set of deliberately ambiguous reports
- **Size**: 950 records, all valid
- **Classes**: `SECURITY` 29.1%, `OTHER` 24.3%, `TECHNICAL` 19.6%,
  `HARASSMENT` 14.2%, `CORRUPTION` 12.8%
- **Fingerprint**: recorded as a SHA-256 in the artifact metadata

**No real report data was used, and none may be.** Report text is confidential.
If real reports are ever exported for training, they must not be committed —
`.gitignore` excludes `ml/data/private/`, and that is where they belong.

## Evaluation

Full numbers in [`model-evaluation.md`](model-evaluation.md). Summary of the
most recent run:

| Metric | Majority baseline | This model |
|---|---:|---:|
| Accuracy | 0.284 | 0.978 |
| Macro F1 | 0.089 | 0.975 |

Evaluated once on a held-out test split of 183 records, grouped by normalised
text so that no duplicated report could appear in both training and test
(verified: zero text overlap). The only model choice — whether to use balanced
class weights — was made on a separate validation split.

Macro F1 is the headline rather than accuracy, because the largest class holds
29% of the data and accuracy would flatter a model that simply leaned towards
it. The baseline's macro F1 of 0.089 is what "always guess the most common
class" is worth.

Again: **these numbers describe performance on generated text.**

## Limitations

1. **Synthetic training data.** Subsumes everything else. Real reports are
   misspelled, elliptical, written under stress, often in a second language,
   and frequently belong to two categories at once.
2. **Small vocabulary** — roughly 960 features from 573 training documents. Any
   real report using words outside it is classified on very little signal.
3. **Class imbalance persists.** The rarest category has the least signal,
   which is exactly where help is most valuable.
4. **Not calibrated.** See the note on "confidence" above.
5. **No fairness evaluation, and none possible here.** Differential performance
   across groups of reporters cannot be measured, because the system collects
   no demographic data at all — a deliberate privacy property that also
   forecloses this analysis. The honest position is that bias is unmeasured,
   not that it is absent.
6. **English only.**
7. **Single held-out split**, no cross-validation.
8. **Categories overlap in reality.** A bribe paid for system access is both
   `CORRUPTION` and `SECURITY`. A single-label model must pick one, and the
   confusion matrix shows it doing exactly that.

## Privacy

- Training runs **entirely locally and offline**. No report text is sent to any
  external service, API or model provider.
- The artifact contains the fitted vectoriser and classifier. It does **not**
  contain training documents.
- The metadata contains the dataset's *filename and SHA-256*, never its
  contents — enough to verify which data produced a model without reproducing
  any of it.
- No secrets, credentials, connection strings or environment values are written
  to any artifact. Tests assert this.
- Report text is never logged by the training pipeline.

## Human oversight

**The model provides suggestions to moderators. It does not make final
decisions.**

This is enforced by the system's structure, not by policy alone:

- suggestions are written to `report_triage`, a table entirely separate from
  `reports`;
- the moderation workflow reads `reports.category` and `reports.status`, which
  only a human sets;
- `report_triage` has its own `status` column describing whether the *inference
  job* ran — a report is fully valid and fully actionable while its triage is
  `PENDING` or `FAILED`;
- the reporter-facing API returns nothing from `report_triage` at all.

A moderator who disagrees with a suggestion simply sets the category they
judge correct. That disagreement is the most valuable training signal the
system can produce, and capturing it is what will eventually replace the
synthetic data this model was built on.

## Priority suggestions are not this model

Priority (`LOW` / `MEDIUM` / `HIGH` / `CRITICAL`) comes from a **documented
deterministic heuristic**, not from a trained classifier — there are no
priority labels in any dataset here to train one on. It is implemented in
`ml/src/priority.py`, returns the signals that fired alongside the level, and
must always be described as a *heuristic priority suggestion*.
